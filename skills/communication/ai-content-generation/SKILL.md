## Purpose

Ensure content *generated by or for* AI systems is gender-inclusive — both the
prompts sent to generative tools and the outputs produced by an agent using this
library.

## When to use

(a) Drafting/reviewing prompts intended for AI tools; (b) generating any content
(articles, scripts, posts, product copy) under this library; (c) reviewing
AI-generated text for inherited bias.

## Rules

### A. Prompt engineering for inclusion
**R1 — Address all audiences explicitly.** Biased default:
> "Create a social media post for a new marketing campaign promoting baby
> nappies. We will have a 25% off promotion for Mother's Day."
Inclusive revision (EIGE-2024):
> "Create three proposals for a social media post … The posts should address all
> parents and family compositions. It will have a 25% discount code valid until
> the end of May."

**R2 — Specify representation requirements in prompts:** roles, family
compositions, avoid gendered defaults ("address all parents", "show diverse
experts"), request neutral colour schemes for visuals.

**R3 — Request multiple proposals** so stereotype-free options can be selected.

### B. Self-audit of generated output
**R4 — An agent using this library applies Tiers 1–3 to its own drafts before
emitting them** — run the same detection pass it would run on external text.
AI tools mirror systemic biases (EIGE-2024): stereotyped professions, default
male voices, "guys", generic he.

**R5 — Virtual-assistant persona design:** do not default assistants to female
voices/personas performing secretarial roles; this perpetuates role assumptions.
If a persona is specified by the client, note the risk once, comply, and log it.

**R6 — Synthetic-media boundary.** Never generate non-consensual intimate
imagery, deepfakes of real people, or content demeaning any group; refuse and
state the boundary plainly (aligns with G12).

### C. Reviewing third-party AI output
**R7 — Treat machine-generated text like any other text:** full
stereotype-detection pass; pay special attention to occupation pronouns,
expert/example genders, and adjective asymmetry (§5 substitution tables).
**R8 — Attribute uncertainty:** when flagging bias in AI output, note that bias
is inherited from training data patterns, not proof of intent.

## Guardrails

- All universal guardrails apply to self-generated content with equal force (G1–G15).
- G15: change logs distinguish "source text was biased" from "our draft was biased".

## Uncertainty

If a client insists on exclusionary framing (e.g. Mother's-Day-only campaign),
comply where lawful/harmless but state the inclusive alternative once in the
response preamble.
